## Validation boundaries

- Native Swift resolver fixtures execute the actual candidate HTTPProtocol on a new macOS APFSX disk image. The fixture proves two differently cased files coexist with distinct contents; a case-insensitive filesystem fails rather than falsely passing. Cases cover exact precedence, unique/multiple-component matches, missing/ambiguous names, Unicode normalization without diacritic folding, symlinks, encoded traversal, nested entries and sibling data directories. This is native macOS Foundation evidence, not a physical iPhone test.
- Actual iOS18.2 selected tests compile the candidate App and run the original diagnostic/import regressions plus existing HTTP server tests and two separate import-confirmation UI tests. Their exact methods/counts and source identities are recorded; this is not the full suite. The current fixture-only retry reuses the already successful run41309016865 at commit11c3fb4ad9cca3a3673ded55cd5ffd0df9271188 only after checking the exact artifact SHA, complete unchanged App/test/runtime inventory, unchanged native runner, and actual summaries/log method sets. - The neutral AS3 fixture is a generated 24fps SWF with ENTER_FRAME scalar traces only. Installed Google Chrome with its default GPU configuration executes the unchanged hash-bound runtime; no unsafe SwiftShader flag or sandbox-disabling argument is added. Default/explicit24/explicit48 wall-clock controls are separate from injected60/120Hz RAF timestamps; the latter do not represent physical displays. Browser sandbox remains enabled. Any failure remains a failure, not an excuse to change the product frame rate.

The reported faster animation has **no established root cause**. No default frame-rate override was found in the actual App configuration. These tests characterize timing independently; they do not certify that a private game's loading or animation issue is fixed. Public fixtures and logs contain no private game names, assets, paths, saves or incident records.
